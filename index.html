Thesis

What we believe, and how we'll know if we're right.

Adding an AI review step to an existing subcontractor RFI form can reduce median GC first-review time by at least 25% compared with the same form completed without AI assistance, without increasing information errors.

The 25% reduction is our proposed target. We will test this claim through our demos during the quarter.

The problem

Unclear questions and missing context can make RFIs harder to understand and review. In RFIs: A contractor's guide to requests for information (2025), Medina and Tell recommend making requests specific and providing enough background information.

That context may include:

  • Where the issue occurs
  • Which work it affects
  • Which people it affects
  • When the answer is needed (the deadline)

These details help the recipient understand the request. If important information is missing, the GC may need to ask the subcontractor for more details before moving forward, which takes extra time and effort. Checking the information before submission could reduce that extra communication and review work.

However, this guidance does not prove that AI will save time. Our proposed experiments will test whether AI assistance actually improves this process.

Building on what exists

Procore already offers an AI feature that helps users draft RFIs and find related project information. Building on this approach, we propose testing an AI check before submission.

Coordination posture

How the AI fits between the subcontractor and the GC, from the subcontractor's side.

Subcontractor

Draft the RFI

Fill out the existing RFI form as usual.

AI agent

Review the draft

Flag missing context, unclear questions, and document references that need checking.

AI agent

Ask for what's missing

If something is unclear, automatically ask the subcontractor for the missing information. Every suggested reference includes its source.

Subcontractor

Review & approve

Check the suggestions, verify sources, and approve the final request.

General contractor

First review

The GC receives a complete RFI and decides if it can move forward.

What the agent does

  • Checks for missing details
  • Flags unclear questions
  • Checks document references, with a source for each so the user can verify it
  • Asks the subcontractor to fill in gaps before the RFI goes to the GC

What the agent will not do

  • Approve design changes
  • Authorize construction work
  • Send an RFI without the subcontractor's approval

Follows the limits on agent authority discussed in class. The human stays in charge of the final request.

Method

We will compare the same form with and without AI, using examples of similar difficulty.

What we measureHow
GC first-review time (main measure)Time the GC from opening an RFI to deciding whether it can move forward or needs more information. Compare median times.
Information errorsCount errors in each RFI.
Requests for clarificationCount how often the GC has to ask for more information.
Subcontractor prep timeRecord how long subcontractors spend preparing each RFI.

Why first-review time

Chin (2009), Work-in-Process and Construction Project Information Flows, found that having more RFIs waiting for review was linked to delays. Our study focuses on how long the GC spends on the first review. It does not measure the total time needed to resolve an RFI or complete the project.

Why we chose them

  • They are finished and the documents are free to use.
  • The RFIs are real questions from contractors, with real answers from the architects.
  • The RFIs use the same format, so they're easy to turn into a table.
  • Each addendum shows which drawings were changed, which we can use as the correct answer when testing our AI agent.

Simulated data

These RFIs come from the bid stage, but our project is about RFIs from a subcontractor to a GC during construction. So we will rewrite some real RFIs in that format, following these rules:

  1. Keep the same problem and drawing numbers.
  2. Add information a subcontractor would include, like location, deadline, and impact.
  3. Make some versions with missing or wrong information, to test whether the agent can find the problems.
  4. Mark every rewritten RFI as "simulated" and link it to the original RFI.

Limitations

What our data can't tell us.

  • The RFIs are from the bid stage, not construction, so our rewritten RFIs are not fully real.
  • We can't get the full original drawings for free. We only have the changed drawings in the addenda.
  • One Pomfret addendum (#3) is missing, so some answers are incomplete.
  • We only have a limited number of real RFIs (exact count to be confirmed), so we will add simulated ones to get more data.

Demo 1: Finding missing details

A working prototype of the AI check on the RFI form, run on simulated cases.

The subcontractor prepares an RFI in one of three modes: without AI (control), with AI (a Gemini check flags missing context before submission), or a rule checklist (offline practice only). A separate GC reviewer then opens the saved RFI blind to the preparation mode, and the app times the first review.

The AI never invents missing dates or approves changes; the subcontractor edits the form themselves.

Demo 2: Checking references

Code + AI review of drawing references against the Dett addenda sheet index, on simulated and real RFIs.

Demo 2 shifts the AI check to drawing references. Code normalizes each cited sheet number and looks it up in a 206-sheet index from six Dett addenda. Gemini then uses each sheet's title to flag possible typos or sheets that may not fit the question. The subcontractor still approves every change; the AI does not authorize work.

The web app includes practice cases R01–R24 (reference tests) and a results tab from batch evaluation. The Evaluation Lab scored the agent on 10 real Dett RFIs against a two-person answer key (agent runs: 8/10 and 9/10 vs a pre-set 8/10 target).
